<li class="rule" data-phase="always"><span class="num">1</span><div class="body"><span class="tag">Always</span><h2 id="rule-1">You merge it, you own it. <a class="rule-link" href="#rule-1" aria-label="Link to rule 1">#</a></h2><p class="what">If it's in your PR, it's your code. <li class="rule" data-phase="plan"><span class="num">2</span><div class="body"><span class="tag">Plan</span><h2 id="rule-2">Write the spec before the prompt. <a class="rule-link" href="#rule-2" aria-label="Link to rule 2">#</a></h2><p class="what">Before I generate anything, I write down what it should do, what it shouldn't touch and how I'll know it works. <li class="rule" data-phase="plan"><span class="num">3</span><div class="body"><span class="tag">Plan</span><h2 id="rule-3">A person defines the interfaces. <a class="rule-link" href="#rule-3" aria-label="Link to rule 3">#</a></h2><p class="what">Types, schemas and API contracts are written by a person. The AI can implement against them, but it doesn't get to change them. Any PR that touches a contract gets a proper look.</p><p class="what">Models are great at filling in a box and bad at deciding where the boxes go. If one is allowed to reshape an interface, every call site turns into a guess and the boundaries between modules quietly rot.</p><figure class="dg"><svg viewBox="0 0 360 172" role="img" aria-label="Both services are built against a contract a person wrote. If it wants to change one, that's a design conversation, not a code suggestion.</p></div></li>

<li class="rule" data-phase="build"><span class="num">4</span><div class="body"><span class="tag">Build</span><h2 id="rule-4">One feature per PR. <a class="rule-link" href="#rule-4" aria-label="Link to rule 4">#</a></h2><p class="what">Each PR does one thing. If a reviewer can't get through the diff in one sitting, split it.</p><p class="what">Agents make it very easy to end up with 2,000 lines touching six things. <li class="rule" data-phase="build"><span class="num">5</span><div class="body"><span class="tag">Build</span><h2 id="rule-5">Expect to iterate. <a class="rule-link" href="#rule-5" aria-label="Link to rule 5">#</a></h2><p class="what">The first output is rarely the one you keep. Run it, read it, adjust the prompt and run it again.</p><p class="what">People treat a bad generation like a bug in the code and start fixing it by hand. It's usually a bug in the spec or the prompt. <li class="rule" data-phase="verify"><span class="num">6</span><div class="body"><span class="tag">Verify</span><h2 id="rule-6">Read every line you ship. <a class="rule-link" href="#rule-6" aria-label="Link to rule 6">#</a></h2><p class="what">Writing code is cheap now. Reading it properly still takes time, and that's where mine should go. If I can't explain a change without asking the AI again, I don't merge it.</p><p class="what">The bottleneck moved.
